> 디자인 기준과 점검표: `docs/앱개발표준.md` (원본 https://claude.ai/artifact/5Efw4RbXGuAhH6LVJii8sc)

앱 목적: (한 줄)

규칙:
1. 기능이 바뀌면 이 문서를 같은 커밋으로 고친다. 앱 버전 = 빌드 번호.
2. 모든 빌드 전에 REQ 반영을 검증하고 '검증 기록'에 남긴다. 자동 시험으로 못 보는 것은 '실기기 확인 필요'.
3. 문제 보고는 바로 고치지 않는다: 고장탐구(재현·원인) → 원인·수정안 보고 → 승인 후 수정.
4. 기능 개선·추가는 초안(화면 모습·동작 규칙·영향 범위·시험 계획) → 확인 → 수정.
5. 안 된다고 섣불리 판단하지 않는다. 직접 시도·시험한 뒤 결과로 말한다.
6. 화면·버튼·창·탭·기능이 바뀌면 이름표(표 + 테두리 그림)를 같이 고친다. 새 부분은 다음 번호, 지운 번호는 다시 안 씀.
7. 화면 변경은 공통 표준 1~6장을 따르고, 8장 점검표를 통과한 뒤 빌드한다.
